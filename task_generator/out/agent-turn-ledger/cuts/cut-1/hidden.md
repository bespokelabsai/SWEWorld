# Hidden requirements — g7 (agent-turn-ledger)

## r1
- **rule** — Beside `responses_0.jsonl` the run directory carries a JSON sidecar named exactly `turn_ledger.json` (module constant `TURN_LEDGER_FILENAME`), written as `json.dumps(ledger.sidecar_state(), indent=2, sort_keys=True) + "\n"` immediately after the seed line is appended and again after EVERY appended response — not batched to the end of `run()` or to `stop_tracker()`. `TurnLedger.sidecar_state()` returns exactly eight keys: `version` (the module constant `TURN_LEDGER_VERSION`, whose value is `2`), `responses`, `turns`, `last_author`, `next_speaker`, `interleave_faults`, `completed`, `completion_reason`. `TurnLedger` carries a twelfth field `status: str`, last in the dataclass field order, whose value is one of the module constant `LEDGER_STATUSES = ("created", "adopted", "verified")`; a ledger the current process built as it wrote is `"created"`. The module exports `read_sidecar(working_dir) -> dict | None`, `write_sidecar(working_dir, ledger) -> str` (returns the absolute path) and `verify_sidecar(working_dir, ledger) -> TurnLedger`.
- **scope** — `load_ledger` is `read_log` + `build_ledger` + `verify_sidecar` and performs no write of any kind; the sidecar is only ever written from `run()`'s append path, so a load that ends in a desync leaves the directory byte-identical. `build_ledger` takes `status: str = "verified"` as its only defaulted keyword.
- **exclusions_or_crossover** — The log is authoritative in every arm: the ledger's `responses`, `turns`, `last_author`, `next_speaker` and `interleave_faults` are always derived from `responses_0.jsonl`, and a sidecar that disagrees with the log is reported as a desync rather than being used to truncate, ignore, or re-order log lines, and rather than being silently repaired in place during the load.
- **failure_behavior** — `verify_sidecar` has exactly three arms. (a) The file is absent, or unreadable as JSON, or its `"version"` is not `TURN_LEDGER_VERSION` → the returned ledger has `status == "adopted"`, no exception is raised, and the file is rewritten from the log on the next append. (b) The version matches AND both `"responses"` and `"last_author"` equal the log-derived values → `status == "verified"`. (c) The version matches and either of those two differs → raise `TurnLedgerDesyncError(TurnLedgerError)` carrying attributes `path` (absolute path of the sidecar), `log_responses`, `recorded_responses`, `log_last_author`, `recorded_last_author`. It propagates out of `run()` before any request is built, so no call to `call_single_request` is made and no line is appended.
- **observability** — Fresh run in an empty dir, seeder `"client"`, partner `"advisor"`, fixed `now_fn`, fake `call_single_request` raising on its first call: `turn_ledger.json` already exists at that moment, its `stat().st_size == 186`, and its text is exactly `{\n  "completed": false,\n  "completion_reason": "open",\n  "interleave_faults": 0,\n  "last_author": "client",\n  "next_speaker": "advisor",\n  "responses": 0,\n  "turns": 1,\n  "version": 2\n}\n`. Against a 3-line log with authors `["client", "advisor", "client"]`: sidecar deleted → `load_ledger(...).status == "adopted"`; sidecar `{"version": 1, "responses": 2, "last_author": "client"}` → `"adopted"`; sidecar `version=2, responses=2, last_author="client"` → `"verified"`; sidecar `version=2, responses=1, last_author="client"` → `TurnLedgerDesyncError` with `log_responses == 2`, `recorded_responses == 1`, `log_last_author == "client"`, `recorded_last_author == "client"`; sidecar `version=2, responses=2, last_author="advisor"` → `TurnLedgerDesyncError` with `log_last_author == "client"`, `recorded_last_author == "advisor"`, and the log still 3 lines with zero generated calls.
- *earlier, reversed*: The first implementation treated the sidecar as the authoritative resume cursor and truncated `responses_0.jsonl` down to the recorded response count on mismatch; a crash between the append and the sidecar write then destroyed a generated turn, so the team reversed it: the log is now authoritative, a stale-but-current-version sidecar is fatal rather than repaired, and a missing or old-version sidecar is benignly adopted.

## r2
- **rule** — `Agent.is_completed(response)` (the base-class body, currently `return False`) returns `True` if and only if `response` is a `str` whose `rstrip()` ends with the sentinel `COMPLETION_SENTINEL == "<<END_OF_CONVERSATION>>"`, defined as a module constant in `turn_ledger.py` and imported by `agent.py`. Matching is case-sensitive, suffix-only, and tolerant of trailing whitespace.
- **scope** — This is the default for every stock `Agent`, not a subclass-only hook, and it is what makes `completion_reason == "agent_signal"` reachable in a run whose agents are constructed by the public constructor; it is consulted on the last log entry via the authoring agent.
- **exclusions_or_crossover** — A message that merely contains the sentinel somewhere other than the end (`"<<END_OF_CONVERSATION>> but wait"`) does not end the conversation; a differently-cased spelling (`"<<end_of_conversation>>"`) does not; and a non-`str` `response_message` — the structured-output `dict`, or `None` — returns `False` rather than raising. The signalling message itself is a full turn and gets identical treatment to any other response: it is appended to `responses_0.jsonl`, counted in `ledger.responses`, counted by `update_turn`, and present as the dataset's last row; the conversation stops after it, not instead of it.
- **observability** — With `A = Agent(name="client", model_name="gpt-4o-mini", ...)`: `A.is_completed("all set <<END_OF_CONVERSATION>>") is True`; `A.is_completed("all set <<END_OF_CONVERSATION>>  \n") is True`; `A.is_completed("<<END_OF_CONVERSATION>> but wait") is False`; `A.is_completed("all set <<end_of_conversation>>") is False`; `A.is_completed("all set") is False`; `A.is_completed({"text": "<<END_OF_CONVERSATION>>"}) is False`; `A.is_completed(None) is False`. End to end with `max_length = 6` and a fake whose third reply is `"Then index funds. <<END_OF_CONVERSATION>>"`: the fake is called `3` times, `len(log lines) == 4`, `tracker.num_responses == 3`, `ledger.completion_reason == "agent_signal"`, and the dataset's last row's `content` is `"Then index funds. <<END_OF_CONVERSATION>>"`.
- *earlier, reversed*: An earlier build used the AutoGen-style bare word `TERMINATE` matched anywhere in the message; it fired on replies that merely discussed terminating, so the team moved to a bracketed sentinel matched only as a suffix (after `rstrip()`) and made the comparison case-sensitive.
