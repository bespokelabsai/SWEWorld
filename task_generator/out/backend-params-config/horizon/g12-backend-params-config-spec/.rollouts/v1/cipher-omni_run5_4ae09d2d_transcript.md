## `config.py` changes

1. **Mode tables and helpers (all new)**:
   - `_MODE_CONFIGS` — maps `"batch"`, `"online"`, `"offline"` to their config classes.
   - `_BACKEND_MODES` — exactly nine entries defining which modes each backend supports.

   - `_remove_none_values(d)` — moved verbatim from `_factory.py`.
   - `_validate_backend_params(params, batch, backend)` — validates against `_MODE_CONFIGS[_resolve_mode(...)]` **only**. The old first-match-wins loop and `ValueError` are gone. Unknown keys are detected by name against `model_fields` *before* pydantic runs, raising `BackendParamError` listing all offenders together (sorted) with the `belongs_to` config classes (in fixed order) that accept *every* offending key.

2. **`BackendModeError(ValueError)`** — with `backend`, `mode`, `supported` attributes and the exact `str()` format.

3. **`BackendParamError(ValueError)`** (from r1) — with `params`, `expected`, `belongs_to` attributes and exact `str()` format including the empty-`belongs_to` tail.

4. **Dead `__post_init__` hooks deleted** — all three removed. 5. **`unsupported_generation_params` field + `model_post_init`** (from r2) — base class hook looks up supported params via litellm and records unsupported ones (sorted); `()` on `None` or any exception. `OfflineRequestProcessorConfig` overrides the hook to set `()` unconditionally. `exclude=True` keeps the field out of `model_dump()`.
