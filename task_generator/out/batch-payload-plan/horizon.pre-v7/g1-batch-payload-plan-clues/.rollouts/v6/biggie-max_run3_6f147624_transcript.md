## Summary

I implemented the ticket in three places:

### 1. New module `src/bespokelabs/curator/request_processor/batch_payload_planner.py`

Pure, testable planner:
- `BatchLimits` (frozen dataclass): `max_requests_per_batch`, `max_bytes_per_batch`, plus `max_batches_per_plan` default 512 (per nikolai/gideon).
- `PlannedBatch` (frozen dataclass): `index, start_idx, end_idx, num_requests, num_bytes` in exact field order (per nils 2025-03-24, dermot 2025-05-14).
- `payload_size_bytes(d)` → `len(json.dumps(d).encode())`.
- `payload_bytes(sizes)` → exact `"\n".join(...)` size, 0 for empty.
- `plan_batches(sizes, limits)` — one greedy pass in index order, contiguous, ordered, exhaustive, keeping spans that land exactly on a limit; empty input → `[]`.
- `BatchPayloadTooLargeError(ValueError)` with `num_requests`, `size_bytes`, `limit_bytes`.
- `SingleRequestTooLargeError(BatchPayloadTooLargeError)` with `row_idx`, `size_bytes`, `limit_bytes`, `num_requests==1`. Checked in index order **before** fragmentation (per nils 2025-06-11).
- `BatchPlanTooFragmentedError(ValueError)` — deliberately **not** a subclass of `BatchPayloadTooLargeError` (per dario 2025-04-24).
- `plan_fingerprint` — sha256 hex[:12] of canonical `start-end:bytes` lines joined by `\n` (dermot 2025-03-17, dario 2025-04-07); empty plan gets stable `e3b0c44298fc` (emil 2025-05-13).
- `plan_document(plan, limits)` — dict with keys in order: `plan_format_version`, `plan_id`, `limits`, `num_batches`, `num_requests`, `num_bytes`, `batches` (emil 2025-04-29, nikolai 2025-04-09, dermot 2025-04-09). Rows are `dataclasses.asdict(PlannedBatch)` verbatim (dermot 2025-05-14).
- `PLAN_FILE_NAME = "batch_plan.json"`, `PLAN_FORMAT_VERSION = 1`.

### 2. `BaseBatchRequestProcessor` updates
- `batch_limits` property packaging `max_requests_per_batch`/`max_bytes_per_batch`.
- `measure_request_payload(generic_request)` — sizes the API-specific payload (what the provider byte cap applies to), not the generic request written to disk.
- `plan_request_batches(dataset)` — measures once in index order using `generation_params_per_row = "generation_params" in dataset.column_names`.
- `create_batch_file` — return annotation now `bytes`; raises `BatchPayloadTooLargeError` (which is still a `ValueError` subclass, keeping existing catchers happy).

### 3. `base_request_processor.py`
- Deleted `_get_optimal_batch_size` and `while True` loop.
- Auto branch: plan first, then sweep only `requests_*.jsonl` and `metadata_*.json` (nothing else, per konrad 2025-04-22), then write `batch_plan.json` with `indent=2` + trailing newline (konrad 2025-05-14), then write each `requests_{p.index}.jsonl` + `metadata_{p.index}.json` via `acreate_request_file`. Returns one path per planned batch in index order; empty dataset → `[]` with `batch_plan.json` still written (gideon 2025-03-14).
- Planner failure leaves the directory untouched (nikolai 2025-04-03, dermot 2025-04-16) — the sweep runs only after `plan_request_batches` returns.
- Explicit-integer `batch_size` branch: byte-for-byte unchanged (konrad 2025-03-14, dermot 2025-06-26) — no planner, no `batch_plan.json`, no sweep, `incomplete_files` still honored.
