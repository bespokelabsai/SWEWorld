## Summary

I made the following changes to replace the ad-hoc sizing loop with a pure, testable planner:

### 1. New file: `src/bespokelabs/curator/request_processor/batch_payload_planner.py`

This pure, dependency-free module exports:
- **`BatchLimits`** — frozen dataclass with `max_requests_per_batch` and `max_bytes_per_batch`.
- **`PlannedBatch`** — frozen dataclass with `index`, `start_idx`, `end_idx`, `num_requests`, `num_bytes`.
- **`payload_size_bytes(api_specific_request)`** — returns `len(json.dumps(d).encode())`.
- **`payload_bytes(sizes)`** — returns the exact size of the `"\n".join(...)` file (`0` for empty).
- **`plan_batches(sizes, limits)`** — walks sizes once in index order, greedily filling contiguous spans. Keeps a batch that lands exactly on either limit. Returns `[]` for no sizes. The plan is exhaustive and ordered (`plan[0].start_idx == 0`, `plan[i].end_idx == plan[i+1].start_idx`, `plan[-1].end_idx == len(sizes)`).
- **`BatchPayloadTooLargeError(ValueError)`** — stores `num_requests`, `size_bytes`, `limit_bytes`.
- **`SingleRequestTooLargeError(BatchPayloadTooLargeError)`** — raised when one request's own size exceeds `max_bytes_per_batch`, stores `row_idx` and `num_requests == 1`.

### 2. `batch/base_batch_request_processor.py`
