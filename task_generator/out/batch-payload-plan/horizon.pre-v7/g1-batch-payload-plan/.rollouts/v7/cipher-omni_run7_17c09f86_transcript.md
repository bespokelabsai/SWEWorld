## Summary

I replaced the ad-hoc sizing loop used by `batch_size="auto"` with a pure, testable planner.

### New file: `src/bespokelabs/curator/request_processor/batch_payload_planner.py`

Exports:
- `@dataclass(frozen=True) BatchLimits` — fields `max_requests_per_batch: int`, `max_bytes_per_batch: int`.
- `@dataclass(frozen=True) PlannedBatch` — fields `index`, `start_idx`, `end_idx`, `num_requests`, `num_bytes`.
- `payload_size_bytes(api_specific_request: dict) -> int` → `len(json.dumps(d).encode())`.
- `payload_bytes(sizes: Sequence[int]) -> int` → exact `"\n".join(...)` file size (`sum(sizes) + (n-1)`, `0` for empty).
- `plan_batches(sizes, limits) -> list[PlannedBatch]` — single forward walk, greedy fill of contiguous/ordered/exhaustive spans, keeps a batch that lands exactly on either limit, returns `[]` for no sizes.
- `class BatchPayloadTooLargeError(ValueError)` — `__init__(*, num_requests, size_bytes, limit_bytes)` storing those as attributes.
- `class SingleRequestTooLargeError(BatchPayloadTooLargeError)` — `__init__(*, row_idx, size_bytes, limit_bytes)` storing `row_idx` and `num_requests == 1`, raised when a single request's own payload exceeds the byte limit (instead of the old `batch_size = 0` hang).

### `BaseBatchRequestProcessor` (`batch/base_batch_request_processor.py`)
- Added a `batch_limits` property built from `self.max_requests_per_batch` / `self.max_bytes_per_batch`.
- Added `measure_request_payload(generic_request) -> int` returning `payload_size_bytes(self.create_api_specific_request_batch(generic_request))` — the provider payload actually submitted, not the generic request written to `requests_*.jsonl`.
- Added `plan_request_batches(dataset) -> list[PlannedBatch]` which builds each row via `PromptFormatter.create_generic_request(row, idx, generation_params_per_row)` (with `generation_params_per_row = "generation_params" in dataset.column_names`), measures each row exactly once in index order, and returns `plan_batches(sizes, self.batch_limits)`.
- `create_batch_file(...)` keeps its signature (return annotation corrected from `str` → `bytes`) and raises `BatchPayloadTooLargeError` where it raised `ValueError` before, so a planned batch's `num_bytes` equals `len(create_batch_file(...))` for that batch.

### `BaseRequestProcessor` (`base_request_processor.py`)
- Deleted the nested `_get_optimal_batch_size` and the `while True` loop.
- The `"auto"` branch now drives off `self.plan_request_batches(dataset)`, writing each planned batch through the existing `acreate_request_file(...)` as `requests_{p.index}.jsonl` with `metadata_{p.index}.json`, and returns `[os.path.join(self.working_dir, f"requests_{p.index}.jsonl") for p in plan]` — one path per planned batch in index order (a 0-row dataset returns `[]`).
- The explicit-integer `batch_size` branch is unchanged: `ceil(len(dataset) / batch_size)` fixed-width files filtered by `incomplete_files`, no byte resplit, no planner call.

`max_requests_per_batch` / `max_bytes_per_batch`, `acreate_request_file` (metadata body `{"num_jobs": n}`) and `run_in_event_loop` are reused as-is. `SingleRequestTooLargeError` is a subclass of `BatchPayloadTooLargeError`, which subclasses `ValueError`, so existing `except ValueError` callers remain compatible.
