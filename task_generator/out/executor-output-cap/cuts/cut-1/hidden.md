# Hidden requirements — g2 (executor-output-cap)

## r1
- **rule** — When a stream's UTF-8 encoding exceeds a non-zero budget, `cap_stream` keeps the FIRST `(max_bytes * 3) // 4` bytes and the LAST `max_bytes - (max_bytes * 3) // 4` bytes (integer floor division; 48 head + 16 tail at max_bytes=64), drops the middle, and joins head to tail with exactly `"\n[[curator:elided {dropped} bytes]]\n"`, where `{dropped}` is the decimal number of bytes actually thrown away — `original_bytes - kept_bytes`, NOT `original_bytes - max_bytes` — with no thousands separator. The marker lives OUTSIDE the budget: the returned `text` is longer than `max_bytes` by exactly the marker's length, `kept_bytes` counts head + tail only and never the marker, and `kept_bytes == original_bytes` when nothing was cut.
- **scope** — The budget is measured on bytes, not characters: `original_bytes` is `len(data.encode('utf-8'))` for `str`, `len(data)` for `bytes`, `0` for `None`. Both slices are trimmed to codepoint boundaries before decoding — for the head, try cutting 0, 1, 2, then 3 trailing bytes and take the first candidate `bytes.decode('utf-8')` accepts; for the tail, try dropping 0, 1, 2, then 3 leading bytes the same way; if no candidate within three bytes decodes (genuinely invalid UTF-8, not merely split), keep the untrimmed slice and decode it with `errors='replace'`. Consequently `kept_bytes` may be strictly less than `max_bytes`, and clean multi-byte input never yields U+FFFD.
- **exclusions_or_crossover** — The non-zero-exit path must hand `_format_exit_code_error` the CAPPED stderr text rather than `result.stderr`, so the `error` string that ships in the response is bounded by the same budget as the `stderr` field; the function's own signature and message format are unchanged. The `files` value from `_collect_sandbox_files` is never capped.
- **observability** — `cap_stream('0123456789' * 10, 64) == CappedStream(text='012345678901234567890123456789012345678901234567' + '\n[[curator:elided 36 bytes]]\n' + '4567890123456789', truncated=True, original_bytes=100, kept_bytes=64)`, so `len(text) == 93 == 64 + 29`, strictly greater than `max_bytes`, with the marker at offset 48. `cap_stream('€' * 10, 20) == CappedStream('€€€€€\n[[curator:elided 12 bytes]]\n€', True, 30, 18)` — `kept_bytes == 18`, exactly six `€`, no U+FFFD. With a fake sandbox returning `exit_code=1, stderr='E'*80, stdout=''` at `max_output_bytes=64`: `output.error == 'Program exited with status code 1\n\nError details:\n' + output.stderr` and `len(output.error) == 143`.
- *earlier, reversed*: The team first counted the notice inside the budget (`len(text.encode()) <= max_bytes` always held, and the omitted count was reported as `original_bytes - max_bytes`); they reversed it once the marker length started varying with the digit count and made the kept-payload size unpredictable, moving the marker outside the budget and switching the count to bytes actually dropped.

## r2
- **rule** — A budget of `0` means UNLIMITED, not empty: `cap_stream(data, 0)` returns the entire stream with `truncated=False` and `kept_bytes == original_bytes`, and does not raise even though `0` is below the minimum, so `max_output_bytes=0` in `backend_params` disables capping outright.
- **failure_behavior** — `cap_stream`, and therefore `cap_execution_streams`, raises `OutputCapError` — exported from `output_cap`, subclassing `ValueError` — whenever `max_bytes != 0 and max_bytes < MIN_MAX_OUTPUT_BYTES` with `MIN_MAX_OUTPUT_BYTES == 16`, i.e. negative values and 1..15. The instance carries an attribute `max_bytes` set to the offending value and the message `f'max_bytes must be 0 or at least 16, got {max_bytes}'`. The validation runs BEFORE the `data is None` check, so `cap_stream(None, 8)` raises rather than returning. `cap_stream(b'x', 16)` does not raise.
- **scope** — Capping is applied at all four `CodeExecutionOutput` construction sites inside `_execute_in_sandbox` — success, the `exit_code == 124` timeout branch, the non-zero-exit branch, and the `except Exception` handler whose streams are salvaged with `getattr(result, 'stdout', None)` and may legitimately be `None` — not only where `result.stdout` / `result.stderr` are first read. A `None` stream is preserved as `None` and never coerced to `''`: `cap_stream(None, 64) == CappedStream(None, False, 0, 0)`; `cap_stream('', 64) == CappedStream('', False, 0, 0)`.
- **observability** — `cap_stream('A' * 100000, 0)` returns text of length 100000 with `truncated=False, kept_bytes=100000` and no exception; `pytest.raises(OutputCapError)` for `cap_stream(b'x', 15)`, `(b'x', 1)`, `(b'x', -1)` and `(None, 8)` with `exc.value.max_bytes` equal to 15 / 1 / -1 / 8. `truncated_streams` names only streams actually cut and is sorted ALPHABETICALLY: `cap_execution_streams('A'*300, 'B'*300, 64).truncated_streams == ['stderr', 'stdout']` in that exact order, `cap_execution_streams('A'*300, None, 64) -> ['stdout']`, `cap_execution_streams('a', 'b', 64) -> []`. With a fake sandbox whose `execute_command` returns `SimpleNamespace(exit_code=0, stdout='A'*300, stderr='')` and whose `__exit__` raises `RuntimeError('boom')`, at `max_output_bytes=64`: `message == 'error'`, `error == 'boom'`, `len(output.stdout) == 94`, `output.stdout.endswith('A' * 16)`, `output.truncated_streams == ['stdout']`, `output.stderr == ''`.
- **exclusions_or_crossover** — The timeout branch gets the identical treatment: a fake returning `exit_code=124, stdout='A'*300` at `max_output_bytes=64` still yields `message == 'timeout'`, `error == 'Execution timed out after 7s'` and `len(output.stdout) == 94` — diagnostic and error paths are not exempted from the cap.
- *earlier, reversed*: The config knob was originally `max_output_bytes: Optional[int] = 65536` where `None` meant unlimited and `0` was rejected, matching how `image` and `base_url` express optionality; it was reversed to a plain non-Optional `int` with `ge=0` and `0` as the disable sentinel, because the YAML/JSON `backend_params` path kept turning an absent key into `None` and silently disabling the cap.
