# Sandbox stdout/stderr output cap

Sandboxed code runs can return unbounded stdout/stderr, which we persist verbatim into the response records, so add a byte budget for sandbox stream output. Build a new module `src/bespokelabs/curator/code_executor/output_cap.py` exposing: `DEFAULT_MAX_OUTPUT_BYTES: int = 65536`; a frozen dataclass `CappedStream` with fields, in declaration order, `text: str | None`, `truncated: bool`, `original_bytes: int`, `kept_bytes: int` (`original_bytes` = UTF-8 byte length of the input — `len(data)` for `bytes`, `0` for `None`; `kept_bytes` = UTF-8 byte length of the retained payload); a frozen dataclass `StreamCapReport` with fields, in declaration order, `stdout: str | None`, `stderr: str | None`, `truncated_streams: list[str]`; and two functions `cap_stream(data: str | bytes | None, max_bytes: int = DEFAULT_MAX_OUTPUT_BYTES) -> CappedStream` and `cap_execution_streams(stdout: str | bytes | None, stderr: str | bytes | None, max_bytes: int = DEFAULT_MAX_OUTPUT_BYTES) -> StreamCapReport`. Neither result type may be a pydantic model, a `NamedTuple`, a dict or a tuple; both must be real frozen dataclasses (`dataclasses.fields` order as listed, `FrozenInstanceError` on mutation). In `types.py`, add `max_output_bytes: int = Field(default=65536, ge=0)` to `CodeExecutionBackendConfig` (so a negative value fails with pydantic `ValidationError`, and the existing `_factory.py` reaches it with no factory edit) and `truncated_streams: list[str] = []` to both `CodeExecutionResult` and `CodeExecutionOutput`. In `code_execution_backend/sandbox_backend.py`, `SandboxCodeExecutionBackend.__init__` stores `self.max_output_bytes: int = config.max_output_bytes`, `execute_request` passes `max_output_bytes=self.max_output_bytes` into its `partial(_execute_in_sandbox, ...)`, and `_execute_in_sandbox(code, code_input, timeout, backend_name, sandbox_kwargs, *, max_output_bytes: int = DEFAULT_MAX_OUTPUT_BYTES)` takes it as a keyword-only parameter (positional passing must raise `TypeError`) and returns capped `stdout`/`stderr` together with a populated `truncated_streams`. `_collect_sandbox_files` and the `files` field are out of scope; existing helpers in `sandbox_backend.py` keep their current names, signatures and message formats. Python 3.10, pydantic v2, no new dependency; tests use the existing fake-`bespokelabs.sandbox` monkeypatch seam.
