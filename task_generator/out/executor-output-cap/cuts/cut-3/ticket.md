# Sandbox stdout/stderr output cap

Sandboxed runs currently return whatever the program wrote, so a runaway `print` loop ships megabytes of stdout through `CodeExecutionOutput` into the response file. Add a configurable byte budget for the stdout and stderr that `SandboxCodeExecutionBackend` returns. `CodeExecutionBackendConfig` (`src/bespokelabs/curator/code_executor/types.py`) gains `max_output_bytes: int = Field(default=65536, ge=0)` — the existing `CodeExecutionBackendConfig(**backend_params)` in `_factory.py:31` already makes it reachable as `CodeExecutor(backend_params={"max_output_bytes": ...})` for every backend name, so no factory edit; a negative value must be rejected at config construction with pydantic's `ValidationError`. In `code_execution_backend/sandbox_backend.py`, `SandboxCodeExecutionBackend.__init__` stores it as `self.max_output_bytes: int`, `execute_request` passes `max_output_bytes=self.max_output_bytes` into the existing `partial(_execute_in_sandbox, ...)`, and the module-level function becomes `_execute_in_sandbox(code, code_input, timeout, backend_name, sandbox_kwargs, *, max_output_bytes: int = 65536) -> CodeExecutionOutput` — keyword-only, after a bare `*`, so a positional sixth argument raises `TypeError`. Both `CodeExecutionResult` and `CodeExecutionOutput` gain a non-Optional `truncated_streams: list[str] = []` holding the names (`"stdout"`, `"stderr"`) of the streams that were shortened on that run; empty, absent or under-budget streams contribute nothing, and the field must survive `CodeExecutionResponse(...).model_dump()`. `files` (from `_collect_sandbox_files`) is not part of this feature, `_format_exit_code_error` keeps its current signature and its exact `"Program exited with status code {status}\n\nError details:\n{stderr}"` message text, and nothing in `_factory.py`, `code_executor.py` or `db.py` changes. Put the capping rule itself in a new module under `src/bespokelabs/curator/code_executor/` rather than inline in the backend, and keep it a pure function of its arguments — no clock, no randomness, no I/O — so it is testable both directly and through the existing fake-`bespokelabs.sandbox` seam used by `tests/code_executor/test_sandbox_backend.py` (`monkeypatch.setitem(sys.modules, "bespokelabs.sandbox", module)` with a `Sandbox` whose `execute_command` returns `SimpleNamespace(exit_code=..., stdout=..., stderr=...)`, plus `monkeypatch.setattr(sandbox_backend, "_collect_sandbox_files", lambda sandbox: "files-archive")`). Python 3.10, pydantic >=2.9.2, no new dependency.
