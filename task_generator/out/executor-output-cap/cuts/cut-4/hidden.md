# Hidden requirements — g2 (executor-output-cap)

## r1
- **rule** — The new capping module is exactly `src/bespokelabs/curator/code_executor/output_cap.py` and its public surface is fixed: constants `DEFAULT_MAX_OUTPUT_BYTES = 65536` and `MIN_MAX_OUTPUT_BYTES = 16`; `cap_stream(data: str | bytes | None, max_bytes: int = DEFAULT_MAX_OUTPUT_BYTES) -> CappedStream` and `cap_execution_streams(stdout, stderr, max_bytes: int = DEFAULT_MAX_OUTPUT_BYTES) -> StreamCapReport`. `CappedStream` is a frozen `@dataclass` with fields, in declaration order, `text: str | None`, `truncated: bool`, `original_bytes: int`, `kept_bytes: int`, where `original_bytes` is `len(data.encode('utf-8'))` for `str` and `len(data)` for `bytes`, and `kept_bytes` is the UTF-8 byte count of the payload that survived. `StreamCapReport` is a frozen `@dataclass` with fields, in declaration order, `stdout: str | None`, `stderr: str | None`, `truncated_streams: list[str]`. Accepting `bytes` as well as `str` is part of the contract.
- **scope** — Both result shapes are plain `dataclasses`, not pydantic `BaseModel`s, not `NamedTuple`s, not dicts and not bare tuples: `dataclasses.is_dataclass(CappedStream)` is True, `isinstance(cap_stream('x', 16), tuple)` is False, `dataclasses.replace` works, and assigning to a field (`cap_stream('x', 16).truncated = True`) raises `dataclasses.FrozenInstanceError`. Nothing in `types.py` becomes a dataclass; the pydantic models keep only the plain `truncated_streams` list.
- **failure_behavior** — `cap_stream` (and through it `cap_execution_streams`) raises `OutputCapError`, defined in the same module as a subclass of `ValueError` carrying the offending value on an attribute `max_bytes`, whenever `max_bytes` is negative or in `1..15` — i.e. `max_bytes != 0 and max_bytes < MIN_MAX_OUTPUT_BYTES`. The check runs before the `data is None` check, so `cap_stream(None, 8)` raises rather than returning, and `cap_stream(b'x', 15)` / `(b'x', 1)` / `(b'x', -1)` raise with `exc.max_bytes` equal to `15` / `1` / `-1`. `cap_stream(b'x', 16)` does not raise and returns `CappedStream('x', False, 1, 1)`.
- **exclusions_or_crossover** — `max_bytes == 0` is exempt from that floor and means *unlimited* rather than *keep nothing*: it does not raise despite `0 < MIN_MAX_OUTPUT_BYTES`, and returns the whole stream with `truncated=False` and `kept_bytes == original_bytes` — `cap_stream('A' * 100000, 0) == CappedStream('A' * 100000, False, 100000, 100000)`, and a backend built with `max_output_bytes=0` returns its streams whole with `truncated_streams == []`.
- *earlier, reversed*: an earlier revision clamped a too-small budget up to the floor instead of raising, and spelled 'no limit' as `max_output_bytes: Optional[int] = None` on the config; both were reversed in favour of raising `OutputCapError` and the `0` sentinel

## r2
- **rule** — When a stream's UTF-8 encoding exceeds the budget, the kept payload is the head-plus-tail of the stream: the first `(max_bytes * 3) // 4` bytes followed by the last `max_bytes - (max_bytes * 3) // 4` bytes (48 and 16 for a budget of 64), with the middle dropped and exactly `"\n[[curator:elided {dropped} bytes]]\n"` spliced at the seam. `{dropped}` is the decimal number of bytes actually discarded — original bytes minus kept bytes, not original minus `max_bytes` — with no thousands separator. The marker is outside the budget: the returned text is longer than `max_bytes` by exactly the marker's length, and the reported kept-byte count never includes the marker.
- **scope** — The budget is counted in UTF-8 bytes, never in characters, and both slices are trimmed to codepoint boundaries before decoding: for the head try cutting 0, 1, 2 then 3 trailing bytes and take the first candidate that decodes; for the tail try dropping 0, 1, 2 then 3 leading bytes and take the first that decodes. A clean multi-byte stream therefore never yields U+FFFD and the kept byte count may land under the budget — a stdout of `'€' * 10` with `max_output_bytes=20` comes back as `'€€€€€\n[[curator:elided 12 bytes]]\n€'` (6 euro signs, 18 kept bytes, no `'�'`). The rule applies identically to stdout and stderr on every return path of `_execute_in_sandbox`.
- **observability** — Driving `_execute_in_sandbox(code='print("hi")', code_input='', timeout=10, backend_name='local', sandbox_kwargs={}, max_output_bytes=64)` against a fake sandbox returning `SimpleNamespace(exit_code=1, stdout='0123456789' * 10, stderr='E' * 80)` gives `output.stdout == '012345678901234567890123456789012345678901234567' + '\n[[curator:elided 36 bytes]]\n' + '4567890123456789'` (len 93), `output.stderr == 'E' * 48 + '\n[[curator:elided 16 bytes]]\n' + 'E' * 16` (len 93), `output.error == 'Program exited with status code 1\n\nError details:\n' + output.stderr` (len 143), and `output.truncated_streams == ['stderr', 'stdout']` — the reported names are sorted alphabetically, not in the stdout-then-stderr order the streams are read in, so the only possible values are `[]`, `['stderr']`, `['stdout']` and `['stderr', 'stdout']`.
- *earlier, reversed*: the first cut reserved room for the notice inside the budget so that the returned text never exceeded `max_bytes`; that was reversed so the marker is additive and the kept payload is exactly the configured budget
