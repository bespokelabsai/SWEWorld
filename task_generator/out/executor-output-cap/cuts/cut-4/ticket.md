# Sandbox stdout/stderr output cap

Sandboxed runs currently return whatever the program wrote, so a runaway `print` loop ships megabytes of stdout through `CodeExecutionOutput` into the response file. Add a configurable byte budget for the stdout and stderr that `SandboxCodeExecutionBackend` returns. In `src/bespokelabs/curator/code_executor/types.py`, `CodeExecutionBackendConfig` gains `max_output_bytes: int = Field(default=65536, ge=0)` — the existing `CodeExecutionBackendConfig(**backend_params)` at `_factory.py:31` already makes it reachable as `CodeExecutor(backend_params={"max_output_bytes": ...})` for every backend name, so no factory edit; a negative value must be rejected at config construction with pydantic's `ValidationError`. Both `CodeExecutionResult` and `CodeExecutionOutput` gain a non-Optional `truncated_streams: list[str] = []` holding the names (`"stdout"`, `"stderr"`) of the streams that were shortened on that run; a stream that is `None`, empty or under budget contributes nothing, and the field must survive `CodeExecutionResponse(...).model_dump()`. In `code_execution_backend/sandbox_backend.py`, `SandboxCodeExecutionBackend.__init__` stores `self.max_output_bytes: int = config.max_output_bytes`, `execute_request` passes `max_output_bytes=self.max_output_bytes` into the existing `partial(_execute_in_sandbox, ...)`, and the module-level function becomes `_execute_in_sandbox(code, code_input, timeout, backend_name, sandbox_kwargs, *, max_output_bytes: int = 65536) -> CodeExecutionOutput` — keyword-only after a bare `*`, so a positional sixth argument raises `TypeError`. The budget must be honoured at every one of that function's four `CodeExecutionOutput` constructions — success, the `exit_code == 124` timeout branch, the non-zero-exit branch, and the `except Exception` branch whose streams are salvaged with `getattr(result, "stdout", None)` and may be `None` — and on the non-zero-exit branch the value handed to `_format_exit_code_error` must be the shortened stderr, not `result.stderr`, so that no unbounded string escapes through `error`; `_format_exit_code_error` itself keeps its signature and its exact `"Program exited with status code {status}\n\nError details:\n{stderr}"` message. `files` (from `_collect_sandbox_files`) is not capped and `_collect_sandbox_files` is untouched; nothing in `_factory.py`, `code_executor.py` or `db.py` changes. Put the capping rule itself in a new module under `src/bespokelabs/curator/code_executor/` that the backend imports, rather than inline in the backend, and keep it a pure function of its arguments — no clock, no randomness, no I/O — so it is testable both directly and through the fake-`bespokelabs.sandbox` seam already used by `tests/code_executor/test_sandbox_backend.py` (`monkeypatch.setitem(sys.modules, "bespokelabs.sandbox", module)` with a `Sandbox` whose `execute_command` returns `SimpleNamespace(exit_code=..., stdout=..., stderr=...)`, plus `monkeypatch.setattr(sandbox_backend, "_collect_sandbox_files", lambda sandbox: "files-archive")`). Python 3.10, pydantic >=2.9.2, no new dependency.
