# Hidden requirements — g2 (executor-output-cap)

## r1
- **rule** — An over-budget stream keeps a head and a tail, never just one end: the first `(max_bytes * 3) // 4` UTF-8 bytes followed by the last `max_bytes - (max_bytes * 3) // 4` bytes (48 + 16 for a 64-byte budget), spliced together with exactly the marker `"\n[[curator:elided {dropped} bytes]]\n"`, where `{dropped}` is the decimal number of bytes actually discarded — `original_bytes - kept_bytes`, not `original_bytes - max_bytes` — with no thousands separator. A stream at or under budget comes back unchanged, with no marker and `truncated=False`.
- **scope** — The marker is outside the budget, not carved out of it: the returned `text` is longer than `max_bytes` by exactly the marker's length (93 characters for a 100-byte ASCII stream at a 64-byte budget), and `kept_bytes` counts only head+tail and never the marker. The budget is counted in UTF-8 bytes of the encoded stream, not in characters, and it is a per-stream budget — stdout and stderr each get the full `max_bytes` rather than sharing one.
- **exclusions_or_crossover** — Both slices land on codepoint boundaries before decoding: for the head, try dropping 0, 1, 2 then 3 trailing bytes and take the first candidate that `bytes.decode("utf-8")` accepts; for the tail, try dropping 0, 1, 2 then 3 leading bytes and take the first that decodes; only if no candidate within three bytes decodes (genuinely invalid UTF-8, not merely split) fall back to the untrimmed slice decoded with `errors="replace"`. So `kept_bytes` may come in under `max_bytes`, and a clean multi-byte stream never yields U+FFFD.
- **observability** — `cap_stream("0123456789" * 10, 64).text` is exactly `"012345678901234567890123456789012345678901234567" + "\n[[curator:elided 36 bytes]]\n" + "4567890123456789"` — `len(...) == 93`, the marker starts at offset 48, `kept_bytes == 64`, `original_bytes == 100`. `cap_stream("€" * 10, 20) == CappedStream("€€€€€\n[[curator:elided 12 bytes]]\n€", True, 30, 18)`: `kept_bytes == 18` (not 20), exactly six `€`, and `"�" not in text`. Through the backend at `max_output_bytes=64` with `stderr="E"*80`, `output.stderr == "E"*48 + "\n[[curator:elided 16 bytes]]\n" + "E"*16`.
- *earlier, reversed*: An earlier revision reserved room for the notice inside the budget (`raw[: max_bytes - len(marker)]`) so that the returned text never exceeded `max_bytes`; it was reversed because callers sizing buffers off `max_bytes` were getting less payload than they asked for, and the team decided the marker rides outside the budget instead.

## r2
- **rule** — `max_bytes == 0` is the sentinel for *unlimited*: the whole stream comes back untouched, `truncated=False`, `kept_bytes == original_bytes`, no marker, and no error despite `0` being below the floor. Every other value under the floor of 16 — i.e. `max_bytes != 0 and max_bytes < 16` — is rejected rather than clamped or honoured.
- **scope** — The floor and the sentinel are enforced inside the capping layer on every call, ahead of any inspection of the data, so a null stream with a bad budget still fails; the config field itself stays permissive (it only rejects negatives at construction), so a too-small-but-non-negative configured value survives config validation and surfaces at capping time.
- **failure_behavior** — Raise `OutputCapError`, a subclass of `ValueError` defined in the capping module, carrying attribute `max_bytes` set to the offending value and the message `f"max_bytes must be 0 or at least {MIN_MAX_OUTPUT_BYTES}, got {max_bytes}"` with the floor exported as `MIN_MAX_OUTPUT_BYTES: int = 16`. It is raised before the `data is None` check, so `cap_stream(None, 8)` raises instead of returning.
- **observability** — `pytest.raises(OutputCapError)` for `cap_stream(b"x", 15)`, `cap_stream(b"x", 1)`, `cap_stream(b"x", -1)` and `cap_stream(None, 8)`, each with `exc.value.max_bytes` equal to `15 / 1 / -1 / 8` and `isinstance(exc.value, ValueError)`; `cap_stream(b"x", 16)` returns `CappedStream("x", False, 1, 1)`; `cap_stream("A" * 100000, 0) == CappedStream("A" * 100000, False, 100000, 100000)`. And the reported names are sorted alphabetically, not in stream/argument order: `cap_execution_streams("A"*300, "B"*300, 64).truncated_streams == ["stderr", "stdout"]`, while `cap_execution_streams("A"*300, None, 64).truncated_streams == ["stdout"]` and `cap_execution_streams("a", "b", 64).truncated_streams == []`.
- *earlier, reversed*: The first version spelled 'disabled' as `None` on the config field (`max_output_bytes: Optional[int] = 65536`) and treated `0` as 'keep nothing'; it was reversed to `ge=0` with `0` meaning unlimited after the Optional made every call site branch on None.
