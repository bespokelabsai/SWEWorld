# Unified model price resolution

Unify how curator resolves model prices. In `src/bespokelabs/curator/cost.py`, add a frozen dataclass `ModelPrice` (fields: `model`, `provider`, `completion_window`, `input_cost_per_million`, `output_cost_per_million`, `source`, `batch`, `output_price_inferred`, `max_tokens`, plus `input_cost_per_token`/`output_cost_per_token` properties) and `UnpricedModelError(LookupError)` (keyword-only `model`/`provider`/`completion_window`/`reason`) as the single success/failure contract for pricing. Add `resolve_model_price(model, *, provider=None, completion_window=None, batch=False) -> ModelPrice`, the one lookup that consults either `litellm.model_cost` or `_DEFAULT_COST_MAP`'s external provider tables and raises `UnpricedModelError` instead of returning `None`-valued prices. Add `register_price_with_litellm(price) -> dict`, the one writer into `litellm.model_cost`, and `format_cost_strings(price, *, rich) -> tuple[str, str]`, the one place display strings for the tracker UI are built. `external_model_cost(model, completion_window="*", provider="default")` becomes a thin shim over `resolve_model_price(..., batch=False)`, keeping its existing signature and dict return shape. Delete `_get_litellm_cost_map`. Rework `_LitellmCostProcessor` (and its `_KlusterAICostProcessor`, `_InferenceNetCostProcessor`, `_AzureCostProcessor` subclasses) so each `cost()` method stops doing its own discount arithmetic and instead multiplies by a `batch_multiplier()` hook that subclasses may override. Give `BatchStatusTracker` and `OnlineStatusTracker` a `refresh_model_price(self, *, price_model=None) -> Optional[str]` method that (re-)resolves and assigns the tracker's price fields and cost display strings, is called from `model_post_init`/`__post_init__`, and is reused by `set_model_cost()` in the batch/azure/mistral request processors so a tracker's prices are identical however it was constructed.
