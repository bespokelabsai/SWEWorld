# Hidden requirements — g13 (raft-document-set)

## r1
- **rule** — Inside `_RaftAnswer`, the pre-randomisation document list is built distractors-first in the order the sampler returned them, with the oracle document APPENDED LAST (the current code prepends it at `raft.py:156`); that list is then permuted by exactly one `self.rng.shuffle(...)` call. `oracle_index` is recovered by carrying a per-slot identity marker through that shuffle (e.g. shuffling `(document, is_oracle)` pairs and reading the marker's position), never by searching the shuffled list for the oracle's text. `parse` then copies `doc_set.oracle_index` and `doc_set.oracle_present` into the row unchanged — the document-set builder is the sole decider and the only producer of the `-1` sentinel; the `... if doc_set.oracle_present else -1` conditional at `raft.py:139` is deleted rather than kept.
- **scope** — The whole draw runs at most once per `(chunk_id, question)` pair: the memoised document-set builder takes the question as a third positional parameter that participates in the `functools.lru_cache` key `(chunk_id, oracle_document, question)` and in nothing else, at `maxsize=512` (today it is `maxsize=128` over `(chunk_id, oracle_document)`, `raft.py:109`). Repeating the same question on the same chunk replays the memoised `DocumentSet` and consumes no randomness; two different questions drawn from the same chunk each get their own independent oracle coin.
- **exclusions_or_crossover** — The oracle-absent branch spends the same shape of rng stream as the present branch, in this order: one `self.rng.random()` coin compared `< self.p`, THEN exactly one `self.sampler(available_indices, k)` call with `k = self.distractors` when the oracle is present and `k = self.distractors + 1` when it is absent, THEN exactly one `self.rng.shuffle(...)` — the shuffle happens in the absent branch too, even though the sampler already returned an unordered subset.
- **failure_behavior** — If the document-set builder hands back an internally inconsistent `DocumentSet` (`oracle_present=False` with `oracle_index=2`), `parse` reports `oracle_index == 2` and `oracle_present is False` as given: it neither masks the index to `-1` nor raises.
- **observability** — (a) Chunks `["same", "same", "other", "third"]` (chunks 0 and 1 share content), `distractors=2`, `p=1.0`, injected `sampler=lambda pop, k: list(pop)[:k]`, injected rng whose `random()` returns `0.0` and whose `shuffle` is a no-op, `chunk_id=0`: `parse({"chunk_id": 0, "question": "Q"}, "resp")["context"]["sentences"][0] == ["same", "other", "same"]` and `["oracle_index"] == 2`. (b) Five chunks, injected spy sampler recording `(population, k)` and a spy rng recording method names: at `p=1.0`, `chunk_id=0` the sampler log is `[([1, 2, 3, 4], 2)]`; at `p=0.0` it is `[([1, 2, 3, 4], 3)]` and the rng log ends with a `shuffle` entry after the `random` entry. (c) Calling the builder with `(0,"alpha","Q1")`, `(0,"alpha","Q2")`, `(0,"alpha","Q1")`, `(1,"bravo","Q1")` gives `cache_info() == CacheInfo(hits=1, misses=3, maxsize=512, currsize=3)` and exactly 3 recorded coins. (d) Stubbing the builder to return `DocumentSet(["x","y","z"], 2, False)` makes `parse` return `oracle_index == 2`.
- *earlier, reversed*: The team first cached on `(chunk_id, oracle_document)` at maxsize=128 and documented `p` as per-example, then reversed: the question joins the key so the coin is drawn per question.

## r2
- **rule** — Before any randomness is consumed, the document-set builder computes `available = len(self.chunks) - 1` and `requested = self.distractors + 1` — the oracle-absent worst case, regardless of how the coin would land — and raises `InsufficientDistractorsError(chunk_id=chunk_id, requested=requested, available=available)` when `available < requested`. It never clamps `k` to the population size and never falls back to a smaller document set.
- **scope** — The check lives in the document-set construction inside `_RaftAnswer`, evaluated on each uncached build, so a too-small corpus surfaces when a row is parsed. Neither `Raft.__call__`, nor `Raft.__init__`, nor the chunking path pre-validates the corpus against `distractors`.
- **failure_behavior** — `class InsufficientDistractorsError(ValueError)` with `__init__(self, chunk_id: ChunkId, requested: int, available: int) -> None`, exposing exactly the attributes `chunk_id`, `requested`, `available`, and `str(exc) == f"chunk {chunk_id}: requested {requested} distractors, only {available} available"`.
- **observability** — Chunks `["a","b","c","d"]`, `distractors=3`, `p=1.0` (the coin would say "oracle present", which needs only the 3 available distractors), injected head sampler and spy rng, `chunk_id=2`: `parse({"chunk_id": 2, "question": "Q"}, "resp")` raises `InsufficientDistractorsError`; `isinstance(exc, ValueError)` is `True`; `(exc.chunk_id, exc.requested, exc.available) == (2, 4, 3)`; `str(exc) == "chunk 2: requested 4 distractors, only 3 available"`; and the spy rng recorded no calls at all.
- *earlier, reversed*: An earlier fix clamped k to the available population so small fixtures kept working; that was reversed in favour of failing up front.
