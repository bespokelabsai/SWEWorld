# Hidden requirements — g13 (raft-document-set)

## r1
- **rule** — `_RaftAnswer` keeps a draw ledger on itself: a new module-level mutable `@dataclass class RaftDrawStats` with exactly two fields, in this order, `document_sets: int = 0` and `with_oracle: int = 0`, plus one method `oracle_rate(self) -> float`. `__init__` sets `self.stats = RaftDrawStats()` (after `self.formatter`). Every document-set build that is actually performed increments `document_sets` by one, and `with_oracle` by one when that build's coin said the oracle is present. Nothing in the block reads `stats`; it exists so a finished run can be asked what oracle rate it realised.
- **scope** — The document-set memo is keyed on `(chunk_id, oracle_document, question)`: the construction helper takes `question: Question` as a third positional parameter which enters the `functools.lru_cache` key and is used for nothing else, `parse` passes `(chunk_id, oracle_document, question)` positionally in that order, and the cache bound is `maxsize=512` (replacing the two-argument key at `maxsize=128` on `raft.py:109`). So the coin, the sampler draw and one ledger increment happen once per `(chunk_id, question)` pair: two different questions on one chunk get independent coins and two ledger entries, while a repeated `(chunk_id, question)` replays the memoised `DocumentSet`, consumes no rng and increments nothing. On the five-chunk fixture, calls `(0,"alpha","Q1")`, `(0,"alpha","Q2")`, `(0,"alpha","Q1")`, `(1,"bravo","Q1")` give `cache_info() == CacheInfo(hits=1, misses=3, maxsize=512, currsize=3)` and exactly three `rng.random()` calls.
- **failure_behavior** — Before any randomness is consumed, the build computes `available = len(self.chunks) - 1` and `requested = self.distractors + 1` — the oracle-absent worst case, regardless of how the coin would land — and raises `InsufficientDistractorsError(chunk_id=chunk_id, requested=requested, available=available)` when `available < requested`. It subclasses `ValueError`, carries the three attributes `chunk_id`, `requested`, `available`, and `str(exc)` is exactly `f"chunk {chunk_id}: requested {requested} distractors, only {available} available"`. With chunks `["a","b","c","d"]`, `distractors=3`, `p=1.0` (a coin that would need only the 3 available distractors), a head-sampler and a recording rng, `parse({"chunk_id": 2, "question": "Q"}, "resp")` raises, `(exc.chunk_id, exc.requested, exc.available) == (2, 4, 3)`, the rng records no calls at all, and the ledger is untouched (`gen.stats == RaftDrawStats()`).
- **observability** — `[f.name for f in dataclasses.fields(RaftDrawStats)] == ["document_sets", "with_oracle"]`; the dataclass is mutable (assigning `stats.with_oracle` works, no `FrozenInstanceError`) and compares by value, so `RaftDrawStats() == RaftDrawStats(document_sets=0, with_oracle=0)`. `oracle_rate()` returns `with_oracle / document_sets`, or exactly `0.0` when `document_sets == 0` — never a `ZeroDivisionError`. On the five-chunk fixture (`distractors=2`, `p=0.5`, `rng=random.Random(7)`, head-sampler) parsed with `(0,"Who?")`, `(0,"What?")`, `(2,"Who?")`, `(0,"Who?")`, `gen.stats == RaftDrawStats(document_sets=3, with_oracle=2)` and `gen.stats.oracle_rate() == 0.6666666666666666` — three, not the four `parse` calls.
- *earlier, reversed*: The counters were first incremented inside `parse`, so cache hits counted too and a repeated question inflated the rate; that was reverted to incrementing only on uncached builds, and the failed-availability path was made to increment nothing.

## r2
- **rule** — `RaftSampling` grows exactly one classmethod, `seeded(cls, seed: int) -> "RaftSampling"`, with `seed` required and positional, returning `cls(sampler=None, rng=random.Random(seed))` — a fresh bundle holding a fresh `random.Random` on every call, so `sampler` stays `None` and the answer generator's default sampler binds to that same rng, making a whole run reproducible from one integer. `RaftSampling.seeded(7).sampler is None`; `isinstance(RaftSampling.seeded(7).rng, random.Random)`; `RaftSampling.seeded(7).rng.getstate() == RaftSampling.seeded(7).rng.getstate()` while `RaftSampling.seeded(7).rng is not RaftSampling.seeded(7).rng`, so `RaftSampling.seeded(7) == RaftSampling.seeded(7)` is `False`; `RaftSampling.seeded(7).rng.random() == 0.32383276483316237`. Through the facade with kwarg-recording stubs, `sampling = RaftSampling.seeded(11)` gives `StubA.kw["rng"] is sampling.rng`, `StubA.kw["sampler"] is None`, and `sampling.rng.random() == 0.4523795535098186`.
- **scope** — In `Raft.__call__`'s list branch, entries whose `str.strip()` is empty are dropped *before* chunk ids are assigned and the survivors are numbered contiguously from `0`: `documents = [t for t in text if t.strip()]` then `[{"chunk_id": i, "content": t} for i, t in enumerate(documents)]`. Surviving text is stored verbatim — surrounding whitespace is kept, only wholly blank entries go. The `str` branch is untouched (`chunk_text` at `raft.py:181` needs no filter). With recording stubs, `Raft(...)(["alpha", "", "  ", "\n", " bravo "])` gives `len(chunks) == 2`, `chunks["content"] == ["alpha", " bravo "]`, `chunks["chunk_id"] == [0, 1]`; an all-blank list gives `len(chunks) == 0` with `chunks.column_names == []` and raises nothing at that point; `"abcdefghij"` still gives `["abcdefghij"]` with `chunk_id == [0]`.
- **exclusions_or_crossover** — The two numeric knobs are validated in `_RaftAnswer.__init__` and only there — `Raft` itself does not re-check, so `Raft(model="m", p=1.5)` constructs happily and fails later when `__call__` builds the answer generator. The checks are the *first* statements of `__init__`, before `super().__init__(*args, **kwargs)`, `p` before `distractors`: `if not 0.0 <= p <= 1.0: raise ValueError(f"p must be in [0.0, 1.0], got {p!r}")`, then `if distractors < 1: raise ValueError(f"distractors must be >= 1, got {distractors!r}")`. Plain `ValueError` in both cases. Both `p` endpoints are legal (`p=0.0` and `p=1.0` construct), `distractors=1` constructs, `distractors=0` and `distractors=-2` are rejected. `p=1.5, distractors=0` together give the `p` message; `_RaftAnswer(chunks=..., model_name="gpt-4o-mini", backend="nope", p=1.5)` raises `ValueError("p must be in [0.0, 1.0], got 1.5")` while the same call without `p` raises `ValueError("Unknown backend: nope")`.
- **failure_behavior** — `RaftSampling.__post_init__` shape-checks a non-`None` `rng` for the three methods the draw uses, in this order — `random`, `shuffle`, `sample` — collecting the ones that are not callable attributes and raising `TypeError("rng must provide " + ", ".join(missing))`. `RaftSampling(rng=object())` raises with `str(exc) == "rng must provide random, shuffle, sample"`; an object exposing only `random()` gives `"rng must provide shuffle, sample"`. The check is structural, never `isinstance(rng, random.Random)`, so duck-typed recorders pass and `RaftSampling(rng=random.Random(7))` passes. `sampler` is not validated at all: `RaftSampling(sampler=42).sampler == 42` constructs, and `RaftSampling()` constructs. `_RaftAnswer` re-checks nothing — constructing it directly with an rng exposing only `random()` succeeds and sets `gen.rng` to that object.
- *earlier, reversed*: An earlier revision put a `seed: int | None` field on `Raft` (materialised into a `Random` inside `_RaftAnswer`) and validated the bundle with `isinstance(rng, random.Random)`; both were reversed — the seed became the `seeded()` constructor, and the isinstance check became the three-method shape check — after the spy doubles in the test suite were rejected by it.
