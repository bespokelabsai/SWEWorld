# Durable response ledger with a single success count

Add `src/bespokelabs/curator/request_processor/response_ledger.py` implementing a durable, file-backed ledger over a run's `requests_N.jsonl` / `metadata_N.json` / `responses_N.jsonl` triples: module constants `LEDGER_SCHEMA_VERSION: int` and `ERROR_SAMPLE_LIMIT: int`; `class LedgerStatus(str, enum.Enum)` with members `SUCCEEDED`, `EMPTY`, `UNPARSEABLE`, `FAILED`; `def classify_record(response: GenericResponse) -> LedgerStatus` that returns `FAILED` when `response_errors` is truthy or `response_message is None`, else `UNPARSEABLE` when `parsed_response_message is None`, else `EMPTY` when it's an empty list, else `SUCCEEDED`; `def ledger_line(response) -> str` / `def parse_ledger_line(line: str) -> Optional[GenericResponse]` for a canonical one-record-per-line JSON serialization (raw provider `response_message` preserved as-is; `BaseModel` rows in `parsed_response_message` normalized via `model_dump(mode="json")`, plain `dict` rows kept, anything else raises `ValueError`; the line ends in exactly one `\n`; a blank or invalid line parses to `None`); `class LedgerIntegrityError(ValueError)` carrying `row_idx: int` and `source_file: str`; a frozen `LedgerTally` dataclass with fields `n_requests, n_declared_requests, n_recorded, n_succeeded, n_failed, n_missing, n_duplicate_lines, n_malformed_lines, n_dataset_rows, error_sample: tuple[str, ...], schema_version: int`; a frozen `ResumeState` dataclass with `completed_row_indices: frozenset[int], retryable_row_indices: frozenset[int], n_dataset_rows: int`; `def read_resume_state(response_file: str) -> ResumeState`; and `class ResponseLedger` with `working_dir`, `classmethod load(working_dir) -> ResponseLedger` (reads every declared request/metadata/response file under the directory, folds every response line for the same `original_row_idx` down to one winning record, and raises `LedgerIntegrityError` for a durable record whose index no `requests_*.jsonl` declares), `.tally() -> LedgerTally`, `.winning_records() -> list[GenericResponse]` (ascending `original_row_idx`), `.missing_row_indices() -> list[int]`, `.unresolved_row_indices() -> list[int]`, and `.request_line(row_idx: int) -> str`. Wire this in: `base_request_processor.py`'s `validate_existing_response_file(self, response_file: str) -> ResumeState` now returns the resume view instead of the tuple it used to, callers use it to decide which requests to skip versus reissue; `create_dataset_files(self, parse_func_hash: str)` builds the dataset and `failed_requests.jsonl` from a loaded `ResponseLedger` instead of its current hand-rolled counters and arrow-derived index set, and `require_all_responses` / all-failed checks are driven off the tally; `_process_response` gains `TypeError` to its existing `(json.JSONDecodeError, ValidationError)` catch so a response body that parses to JSON but isn't a mapping can't crash the request loop. In `online/base_online_request_processor.py` and `batch/base_batch_request_processor.py`, every terminal response — success, empty parse, unparseable parse, or permanent failure — is written to `responses_N.jsonl` via `ledger_line` rather than only successes (`append_generic_response`'s and `_process_single_response`'s current early returns on an empty/`None` parse are removed), and `offline/base_offline_request_processor.py`'s `process_requests_from_file` writes through the same helper. `types/curator_response.py`'s `update_tracker_stats(self, tracker, tally: Optional[LedgerTally] = None) -> None` computes `RequestStats` (`total`, `succeeded`, `failed`) from the tally for both online and batch trackers when one is supplied, instead of the current per-mode in-memory counters; `llm.py`'s call site passes the loaded tally through.
