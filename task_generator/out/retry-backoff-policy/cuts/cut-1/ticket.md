# Failure-class retry policy for online requests

Add a failure-class retry policy for online request processing. Create a new pure module `src/bespokelabs/curator/request_processor/online/retry_policy.py` (standard library only — `dataclasses`, `enum`, `typing`; it must not import `aiohttp`, `time` or `random`) containing: `class FailureClass(str, enum.Enum)` with exactly the members `THROTTLE = "throttle"`, `TRANSIENT = "transient"`, `CONTRACT = "contract"`, `TERMINAL = "terminal"` in that declaration order; `classify_failure(exc: BaseException) -> FailureClass`, which never raises and consults four signals, returning on the first that matches — (1) an `int` HTTP status read from `getattr(exc, "status_code", None)` falling back to `getattr(exc, "status", None)`, matched against `400 -> CONTRACT`, `401/403/404 -> TERMINAL`, `408/409/425 -> TRANSIENT`, `413/422 -> CONTRACT`, `429/529 -> THROTTLE`, with any other status in 500-599 mapping to `TRANSIENT` and any other `int` (or non-`int`) falling through to the next signal; (2) the exception type, matched by `__name__` walked along `type(exc).__mro__` in order against `TimeoutError/ConnectionError/ClientConnectorError -> TRANSIENT`, `ValueError/ValidationError/JSONDecodeError/KeyError -> CONTRACT`, `PermissionError/NotImplementedError -> TERMINAL`; (3) substrings of `str(exc).lower()`, scanned in table order — `"rate limit"`, `"ratelimit"`, `"too many requests"`, `"overloaded"`, `"quota"` -> `THROTTLE`; `"timed out"`, `"timeout"`, `"connection reset"`, `"temporarily unavailable"`, `"response is empty"` -> `TRANSIENT`; `"invalid api key"`, `"authentication"`, `"permission denied"` -> `TERMINAL`; (4) a `TRANSIENT` default. Also define `@dataclasses.dataclass(frozen=True) class RetryVerdict` carrying `should_retry`, `failure_class`, `attempt_index` (1-based index of the attempt that just failed), `delay_seconds` (`>= 0.0`, and `0.0` whenever `should_retry` is False), `attempts_left_after`, `tracker_field` (the name of the single `OnlineStatusTracker` counter this failure belongs to: `THROTTLE -> "num_rate_limit_errors"`, `TRANSIENT`/`TERMINAL` -> `"num_api_errors"`, `CONTRACT -> "num_other_errors"`) and `reason_code` (`f"{failure_class.value}:{outcome}"`, where `outcome` is one of `"retry"`, `"exhausted"`, `"abort"`); `class RetryPolicy` with `__init__(self, clock: t.Callable[[], float], jitter: t.Callable[[], float]) -> None` (both injected, neither defaulted), `delay_for(failure_class: FailureClass, attempt_index: int) -> float` giving the exponential-backoff wait for that class and attempt, `decide(exc: BaseException, *, attempts_made: int, attempts_left: int, ...) -> RetryVerdict` which classifies the exception and prices it against the request's remaining retry budget without mutating anything, and `apply_to_tracker(tracker: t.Any, verdict: RetryVerdict) -> None`, which increments exactly the counter named by `verdict.tracker_field` and, for throttle verdicts only, stamps `tracker.time_of_last_rate_limit_error` and extends (but does not shorten) `tracker.throttle_cooldown_until` — a new `OnlineStatusTracker` dataclass field, `throttle_cooldown_until: float = 0.0`, placed immediately after `time_of_last_rate_limit_error`; `remaining_cooldown_seconds(tracker: t.Any, now: float) -> float` returning `max(0.0, round(tracker.throttle_cooldown_until - now, 3))`; `format_failure_summary(failure_log: t.Sequence[tuple[FailureClass, str]]) -> list[str]`, one `f"[{failure_class.value}] {message} (x{count})"` entry per distinct `(class, message)` pair, sorted by count descending with ties broken by first occurrence in the log, `[]` for an empty log; and `format_attempt_label(attempts_made: int, max_retries: int) -> str` returning `f"attempt #{attempts_made + 1} of {max_retries + 1}"`. `APIRequest` gains `attempts_made: int = 0` and `failure_log: list = field(default_factory=list)` (appended after the existing fields, `attempts_left` keeps its name and its seeding from `config.max_retries`); `BaseOnlineRequestProcessor.__init__` builds `self.retry_policy`; the `except Exception as e:` block in `handle_single_request_with_retries` is rewritten to call `decide` then `apply_to_tracker`, append `(verdict.failure_class, str(e))` to `request.failure_log`, write the verdict's budget values back onto the request, and — when `should_retry` — log the class and `reason_code`, set `request.retry_not_before` from the verdict delay and re-queue, otherwise emit the usual `GenericResponse` with `response_errors=format_failure_summary(request.failure_log)`. `cool_down_if_rate_limit_error` is rebuilt on `remaining_cooldown_seconds`, the retry loop's attempt log uses `format_attempt_label`, and the hand-rolled rate-limit blocks in the openai/anthropic/litellm processors stop mutating tracker counters (their compensating `num_api_errors -= 1` / `num_other_errors -= 1` lines are deleted) while still raising.
