# Hidden requirements — g4 (run-cache-identity)

## r1
- **rule** — Of everything in `llm.backend_params`, exactly four keys participate in the run key — `azure_deployment`, `base_url`, `batch_size`, `completion_window`, declared as the module constant `IDENTITY_BACKEND_PARAM_KEYS: frozenset[str]` — and every other backend param is dropped before the components are serialised or hashed; the `backend` component is the backend name the request processor resolved (`self._request_processor.backend`), not the `backend=` argument the caller declared.
- **scope** — Applies to the identity component dict for any duck-typed llm object, and therefore to `run_hash`, to the cache directory name, and to the `components` block written into `run_identity.json`. Only the identity's view is filtered: the full `backend_params` dict still reaches the request processor unchanged, and `LLM.backend_params` still returns all of it.
- **exclusions_or_crossover** — Changing `api_key`, `max_retries`, `request_timeout`, `require_all_responses`, `batch_check_interval`, `max_requests_per_minute`, `seconds_to_pause_on_rate_limit` or `delete_successful_batch_files` must leave `run_hash` byte-identical, so the run lands in the same directory and still hits cache — `api_key` is excluded deliberately even though it changes what comes back, because the components are written to disk in cleartext. Changing `base_url`, `batch_size`, `completion_window` or `azure_deployment` must fork the run. `LLM(model_name="gpt-4o-mini")` and `LLM(model_name="gpt-4o-mini", backend="openai")` are the same run.
- **failure_behavior** — A component value that `json.dumps` cannot serialise raises `RunIdentityError` — no `default=str`, no `repr` fallback, and no bare `TypeError` escaping.
- **observability** — With stub `S` whose `backend_params == {"base_url": "https://x/v1", "max_retries": 7, "api_key": "sk-secret", "request_timeout": 30}`: `compute_run_identity(S, "d0").components["backend_params"] == {"base_url": "https://x/v1"}`; `compute_run_identity(S, "d0").run_hash == compute_run_identity(S2, "d0").run_hash` where `S2` differs only in `max_retries=999, api_key="sk-other"`; a differing `base_url` gives a different `run_hash`; and after the stamp is written, `"sk-secret"` appears nowhere in `run_identity.json` on disk.
- *earlier, reversed*: An earlier build hashed the whole `backend_params` dict (api_key and retry knobs included) the same way `generation_params` is hashed today; reversed once the components started being written to disk in cleartext and retry-tuning began forking caches.

## r2
- **rule** — `reconcile_run_directory` reports one of exactly four status strings on `RunDirectoryCheck.status`: `"created"` when the directory is missing or exists with zero entries (create it with `parents=True, exist_ok=True`, write the stamp, `previous_version=None`); `"adopted"` when it is non-empty but carries no readable stamp (write the stamp, delete nothing, `previous_version=None`); `"upgraded"` when the stamp's `identity_version` is below `RUN_IDENTITY_VERSION` (rewrite it under the current identity while preserving the old stamp's `created_at`, `previous_version` = the old int); `"matched"` when the stamp is the current version with the same `run_hash` and equal `components` (refresh `updated_at` only, `previous_version=3`).
- **scope** — Runs against the run cache directory named by `run_hash`, before the run reads or writes anything else in it, on every `LLM.__call__` — including disabled-cache directories, which are reconciled the same way.
- **exclusions_or_crossover** — A non-empty, stamp-less directory from a pre-v3 cache is adopted and left intact — not refused and not cleared, the opposite of this repo's habit of raising and telling the user to `rm -rf ~/.cache/curator`; the corrupt-arrow-file path in `attempt_loading_cached_dataset` keeps its own clear-and-rerun behaviour and is not folded into reconciliation.
- **failure_behavior** — Disagreement raises `RunIdentityMismatch` and leaves the directory byte-for-byte untouched (no stamp rewrite, no file created or deleted). The exception carries `path`, `expected_run_hash`, `found_run_hash` and `mismatched_components`: a stamp whose `identity_version` is above `RUN_IDENTITY_VERSION` gives `mismatched_components == ("identity_version",)`; a current-version stamp with a different `run_hash` or differing components gives the alphabetically sorted tuple of the component keys whose values differ, or `("run_hash",)` when the stamp carries no comparable components.
- **observability** — Empty `tmp_path/"a"` → `status == "created"`, `previous_version is None`, `len(os.listdir(a)) == 1`. `tmp_path/"b"` holding `payload.txt` → `status == "adopted"`, `previous_version is None`, `sorted(os.listdir(b)) == ["payload.txt", "run_identity.json"]` with `payload.txt` unchanged. `tmp_path/"c"` pre-stamped `identity_version=2, created_at="2024-06-01T00:00:00"` → `status == "upgraded"`, `previous_version == 2`, stamp now version 3 with `created_at` still `"2024-06-01T00:00:00"`; reconciled again → `status == "matched"`, `previous_version == 3`, only `updated_at` moves. `tmp_path/"d"` stamped `identity_version=4` → `RunIdentityMismatch` with `mismatched_components == ("identity_version",)`. `tmp_path/"e"` stamped with another identity differing in `model_name` and `parse_func_hash` → `RunIdentityMismatch` with `mismatched_components == ("model_name", "parse_func_hash")`, `found_run_hash` equal to the stamp's hash, and `os.listdir(e)` unchanged.
- *earlier, reversed*: The first cut followed `validate_schema`'s house style: any unrecognised or unstamped directory raised `RuntimeError` pointing at `rm -rf ~/.cache/curator`, and stamp-less directories were briefly wiped and re-created; reversed to adopt-and-stamp, upgrade-in-place, and raise-without-touching-files.
