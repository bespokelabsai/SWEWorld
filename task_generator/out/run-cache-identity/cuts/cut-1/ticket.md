# Versioned run identity for the curator cache

Add versioned run identity to the curator cache, replacing the ad-hoc fingerprint. Create a new top-level module `src/bespokelabs/curator/run_identity.py` (top-level, not under `llm/`, so `db.py` can import from it without a cycle) exporting `RUN_IDENTITY_VERSION: int = 3` and `RUN_IDENTITY_FILENAME: str = "run_identity.json"`; the exception family `RunIdentityError(RuntimeError)`, `RunIdentityMismatch(RunIdentityError)`, `CachedResponseMismatch(RunIdentityError)`; the frozen dataclasses `RunIdentity(run_hash, digest, identity_version, cache_enabled, components)`, `RunStamp(identity_version, run_hash, digest, components, created_at, updated_at)` with `to_dict()` / `from_dict()`, and `RunDirectoryCheck(status, stamp, previous_version)`; and the functions `compute_run_identity(llm, dataset_hash, *, cache_enabled: bool = True, run_id: Optional[str] = None) -> RunIdentity`, `write_run_stamp(run_cache_dir, identity, *, now: str, created_at: Optional[str] = None) -> RunStamp`, `read_run_stamp(run_cache_dir) -> Optional[RunStamp]` (returns `None` when the file is absent or unreadable; it does not raise), and `reconcile_run_directory(run_cache_dir, identity, *, now: str) -> RunDirectoryCheck`, which decides what a run does with the directory it is about to use and stamps it. The identity duck-types its `llm` argument (no `isinstance`, no import of `LLM`) and reads `llm.prompt_formatter.{prompt_func, parse_func, model_name, response_format, generation_params, system_prompt}`, `llm.batch_mode`, `llm.backend`, `llm.backend_params` and `llm.return_completions_object`, plus the dataset hash and the optional run id; the two function components use `_get_function_hash`, which moves verbatim out of `llm/llm.py` into this module and stays importable from its old home; `digest` is an `xxh64` hexdigest over a deterministic JSON serialisation of the components, and `run_hash` is the name of the run's cache directory. The module reads no clock and no randomness — every timestamp and every run id arrives as a parameter — and `write_run_stamp` writes the six-key stamp (`identity_version`, `run_hash`, `digest`, `components`, `created_at`, `updated_at`) into `RUN_IDENTITY_FILENAME` in the run directory, `created_at` defaulting to `now`, `updated_at` always `now`. Wire it up: `llm.py` deletes `_hash_fingerprint()` in favour of `LLM._run_identity(dataset_hash, *, cache_enabled, run_id=None)`, adds `backend` and `backend_params` properties (`backend_params` is a copy of what was passed to `__init__`, `{}` when `None`), takes a `run_id` keyword on `__call__` (defaulting from `CURATOR_RUN_ID` or a fresh `uuid4().hex`) and reconciles the run directory before using it, and `_get_cached_response` re-raises `RunIdentityError` while still returning `None` with the existing warning for every other exception; `db.py` gains `RUNS_COLUMNS`, writes `parse_func` and `identity_version`, and `validate_schema()` migrates missing columns forward and returns the tuple it added while still rejecting unexpected ones; `types/curator_response.py` gains `run_identity: Optional[Dict[str, Any]] = None` declared last and emitted by `to_dict()`, and `load(cache_dir, dataset, *, verify: bool = True)` checks the recorded dataset block against the dataset it is handed and raises `CachedResponseMismatch`; and `BaseRequestProcessor.run()` resets `_is_cached_dataset` as its first statement. No new dependency; Python 3.10 target.
